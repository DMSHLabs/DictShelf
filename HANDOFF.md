Keep this relay enabled whenever the parent binding exists; workspace dialogs may lack the `wudict_webview2` URL marker even when running in the Windows WebView.

Windows WebView2 answers GET requests through a local replacement of `github.com/jchv/go-webview2` at `third_party/go-webview2`. The bridge forwards Range and conditional request headers. Responses up to 8 MiB stay in memory; larger responses spill to a temporary file-backed COM `IStream` that WebView2 reads after the handler returns. The temporary path is removed after handing off the stream while its retained COM reference remains readable. No response-size limit remains in the in-process path, but a large request without Range must finish writing its temporary file before WebView2 can read it. The desktop window uses the secure origin `https://wudict2.local/` with WebView2's `WebResourceRequested` event routing requests directly through Go; it does not map the origin to a static folder. On first launch, the old loopback page is loaded hidden to export localStorage into the new origin, and later launches go directly to the new origin. The old HTTP listener remains active during this transition and for browser fallback.

Windows WebView2 marks every document at creation, including pages reached through in-app navigation, so desktop layout and local appearance storage stay active across pages. The `← Words` return link appears in the top bar before `wuDict2`; the duplicate status-bar link stays hidden. Dictionary selection uses the same in-page group, dictionary and search/filter dialog in browser, Windows WebView2 and Android WebView; Android's old native dictionary dialog and prompt route are removed.

The six main workspace surfaces share the full-window frame: Dictionary Settings, Dictionary Groups, Browse, Edit Filters, Edit Folders and Lemmatization. The three editors open in one reusable modal iframe over the app, with a 10px inner gutter filled by the paper background. The iframe is anchored to all four dialog edges; each editor keeps its title fixed and scrolls only its content area. Edit Folders places its scrollbar at the card's right edge; Lemmatization scrolls only its checkbox list while keeping the directory note and attribution visible. Edit Filters keeps its saving status and Save on one non-wrapping action row; the status itself can wrap. Edit Folders no longer shows its separate top banner while applying folder changes; the shared bottom work-progress indicator owns that operation. Rescan Folders uses the same 560px maximum panel width as Dictionary Groups on desktop and 16px side gutters on narrow screens; its scrollbar reaches the panel edge like Edit Folders while content retains its inset.

In Dictionary Groups, the member and available-dictionary panels stay visible. When either panel is active, they split the available height evenly if each half fits ten rows; otherwise the active panel grows toward ten rows while preserving one row in the other panel.

The Android WebView marks itself explicitly before calling the paper appearance bridge. The page sends `field:"paper"` only for Android; Windows appearance requests use the page's local desktop store. The Windows WebView2 host also intercepts `wudict:appearance` prompts from restored older pages and routes them to the desktop appearance store before a native JavaScript dialog appears.

Windows portable mode uses `Data` beside the executable when it contains `Dictionaries` and `wudict2.toml`. It stores the database and lemmas under `Data`, resolves relative paths there, and rewrites their configured paths on startup. A legacy `wudict.toml` is copied to `wudict2.toml` when needed. Copied prepared indexes are relinked to dictionary copies by filename, size and source fingerprint, so moving a portable folder does not require rebuilding them. Invalid portable data reports the problem and falls back to the regular user data folder. Windows uses `wudict2.toml`; other platforms retain `wudict.toml`.

Windows migration from `~/.wudict` to `~/.wuDict2` carries wuDict2's prepared database, logs, lemmas, styles and settings, and rewrites paths in the imported config. Upstream-only index data is not imported.

Newly added dictionaries and previously known dictionaries with a missing index queue the mandatory headword index, unless the index was explicitly removed. Before queuing, rescan reuses a current prepared index at the same path, relinks a moved source, or relinks a matching copy when its old source is outside the selected folders. A completed index also clears a stale pending receipt when it satisfies the requested plan. Saved defaults select only Contains and full-text. Search does not build a missing index; it skips that dictionary. The focused tests cover both rules.

Fork-specific dictionary groups, mask search, migration and Android identity remain enabled. Upstream how-to and wildcard features remain unwired as recorded in `AGENTS.md`.
