# Interface translation — first slice

The reader chooses **Language → English / Русский → Apply and reload**.
English is the default. There is no automatic choice from the OS, Android
configuration, `Accept-Language`, browser locale, or dictionary metadata.
The setting belongs to this server installation (all clients of that server),
is saved beside the other preferences in `state.json`, and survives a port
change. An already open page keeps its language until reloaded.

## Current scope

- Language is available in the Settings drawer, on Edit Folders (including
  first run), and on Browse.
- Browse's interface is translated: chooser, navigation, counts, tooltips,
  page title, progress, empty state and actionable errors. Technical error
  details may remain in the server's original language.
- The remaining app interface, Edit Folders itself, Lemmatization, and native
  Android resources are still English. The current debug APK was built with
  `build-android.cmd debug intel` and, with explicit user approval, installed
  over wuDict2 Debug on emulator-5554, preserving app data (versionCode 417).
- Dictionary names, headwords, articles, identifiers, search, word selection
  and speech are untouched. In particular the main page retains `lang="en"`
  during partial translation, so `pick.js` keeps its existing fallback. Before
  translating the main document's `lang`, isolate that fallback from UI locale.

## Extending the translation

Catalogs are `internal/server/web/i18n/en.json` and `ru.json`. Stable semantic
keys name whole messages, not fragments assembled around dictionary data.
`{{T:key}}` is for static HTML text or quoted attributes: the server escapes
the translation and inserts it before serving. Do not use it in JavaScript,
CSS, URLs, or raw HTML. `{{I18N}}` adds the bootstrap and hashed shared assets.

Dynamic UI code uses `window.wudictI18n.t(key, parameters)`. It returns plain
text: use `textContent`, or escape it with the page's existing helper before
putting it in HTML. Never translate an article or walk dictionary DOM nodes.
Plural entries are objects keyed by Intl.PluralRules categories; pass the
numeric `count` separately from the displayed `number`. Parameters are
substituted once, so a dictionary title containing `{name}` remains literal.

Missing translations fall back to English; an unknown key remains visible.
Catalog checks require complete shipped catalogs, matching parameter names,
and the applicable plural forms. They check explicit references, not every
new English literal upstream might add. Review UI diffs during upstream merges.
The existing merge-work comparison script has not been changed in this slice.

The language endpoint updates only the language, under the preferences locks,
with rollback on write failure. Old tabs saving `/api/prefs` cannot overwrite
it. Main-page cache keys and ETags include the language. Page reload applies
the choice without restarting Go; native Android integration is a later slice.
